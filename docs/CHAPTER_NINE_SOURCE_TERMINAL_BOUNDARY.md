# 第九章终局边界：来源问题与候选修正

## 已证实

原 HTML 来源在最后一夜结束后将内部 day 从 48 加到 49，并标记 end/ended。照片合同仍拒绝 day > 48。只读来源审计的 11 条正常终局均出现「候选存档未写入：照片合同日期无效。」，保留前一次模拟 localStorage 内容。此审计使用 VM 存储桩，不代表真实浏览器磁盘验收。

证据：evidence/chapter_nine_source_terminal_save_audit.json。原来源、原黄金结果未修改。

候选原生存储另做实际文件写入及新 Godot 进程读回。五条终局轨迹通过，包含三个不同 C8 父状态及两个替代日间策略，不是全部结局或从新游戏开始的完整 49 日验证。证据：evidence/native_chapter_nine_candidate_disk.json。

## 原生候选处理

内部 day=49、ended=true 的终局状态保留。来源对照仅对已确认的这一条终局浏览器保存错误作显式排除，不能把来源报错当成原生应复制的游戏状态。

部分来源后记需要 day=48，在正常终局 day=49 时不出现。候选显示模型只在独立深拷贝中以最后可游玩日生成后记；不改真实状态、随机数或存档。显示投影测试 12 个正常/失败样本，60 项检查通过。保存摘要显示「四十九日结束」，不能将终局哨兵日误写为第 50 日。
